# E-CMIS Integration Mockup

## Register

product

## Users

เจ้าหน้าที่สำนักงาน ป.ป.ท. ที่สืบค้นข้อมูลประกอบสำนวนคดี ผู้บังคับบัญชาที่ตรวจสอบผล และทีม IT, SA, Dev และ QA ที่ต้องยืนยันความพร้อมของบริการเชื่อมโยงข้อมูล หน้าจอต้องช่วยให้เจ้าหน้าที่แยกบุคคลที่ชื่อซ้ำได้โดยไม่เปิดเผยข้อมูลเกินจำเป็น และนำข้อมูลที่ยืนยันแล้วเข้าสำนวนอย่างมีหลักฐานตรวจสอบย้อนหลัง

## Product Purpose

Prototype นี้ใช้ตกลง Workflow กับลูกค้าและเป็นสัญญาการออกแบบเบื้องต้นสำหรับการเชื่อมโยง API ภายนอก โดยเฉพาะ DOPA Linkage Center 2 ระบบต้องสะท้อน Input, Output, สิทธิ์ และสถานะรายบริการตาม Spec จริง แยกข้อมูลที่ยืนยันแล้วออกจากข้อมูลสมมติ และไม่ทำให้ Sandbox Mock ดูเหมือนการเชื่อม Production สำเร็จ

## Brand Personality

เป็นทางการ ชัดเจน และน่าเชื่อถือ ภาษาบนหน้าจอควรเป็นภาษาเจ้าหน้าที่งานคดี ไม่ใช้ภาษาการตลาด และเปิดเผยรายละเอียดทางเทคนิคเฉพาะเมื่อผู้ดูแลระบบต้องใช้

## Anti-references

ไม่ใช้หน้าแบบ Landing Page, Dashboard ที่มีการ์ดตกแต่งจำนวนมาก, สีฉูดฉาด, ข้อมูลเทคนิคเต็มหน้าจอ, ตารางขนาดใหญ่โดยไม่มีลำดับการตัดสินใจ หรือข้อมูลทะเบียนที่ไม่ได้ยืนยันจาก Spec ห้ามใช้สีเพียงอย่างเดียวเพื่อสื่อสถานะ และห้ามดึงข้อมูลอ่อนไหวของผู้สมัครทุกคนก่อนเจ้าหน้าที่เลือกตัวบุคคล

## Design Principles

1. เริ่มจากงานที่เจ้าหน้าที่ต้องทำ แล้วเปิดรายละเอียดเมื่อจำเป็น
2. ทุกข้อมูลบนหน้าจอต้องย้อนกลับไปยัง Service และฟิลด์ใน Spec ได้
3. ใช้ข้อมูลขั้นต่ำเพื่อแยกบุคคลที่ชื่อซ้ำ ก่อนเรียกข้อมูลละเอียด
4. แยกสถานะไม่พบข้อมูล ไม่มีสิทธิ์ และบริการขัดข้องอย่างชัดเจน
5. การนำเข้าสำนวนต้องป้องกันบุคคลซ้ำและเก็บแหล่งข้อมูลกับเวลาที่นำเข้า

## Accessibility & Inclusion

รองรับการใช้งานด้วยคีย์บอร์ด มี Focus ที่มองเห็นได้ ใช้ข้อความและไอคอนร่วมกับสี สถานะสำคัญต้องอ่านได้บนหน้าจอขนาดเล็ก และเนื้อหาภาษาไทยต้องไม่ถูกตัดหรือทับกัน
