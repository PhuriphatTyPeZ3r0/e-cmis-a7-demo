# เล่ม 7 — ออกแบบส่วนการติดต่อกับผู้ใช้งาน (User Interface Design) และออกแบบ Prototype
## กิจกรรมที่ 7 พัฒนาระบบบริหารจัดการกระบวนงานพิจารณาและดำเนินการตามมติคณะกรรมการ ป.ป.ท.

โครงร่าง (outline) นี้เทียบเคียงโครงสร้างกับ **เล่ม 4** (ออกแบบส่วนการติดต่อกับผู้ใช้งานฯ กิจกรรมที่ 4) แต่ปรับตัวแปรหลักจาก
"ช่องทางรับเรื่อง" (20 ช่องทาง) เป็น **"บทบาทในสายอนุมัติ/สถานะสำนวน"** เนื่องจากกิจกรรมที่ 7 ไม่มีช่องทางเข้า
หลายทางแบบกิจกรรมที่ 4 — ตัวแปรที่ทำให้แต่ละหน้าจอ/ขั้นตอนต่างกันคือ "ใครเป็นเจ้าของคิวงานในสถานะนั้น"

**อ้างอิง TOR ที่ใช้:**
- **ข้อ ๒.๑.๓ / ๒.๑.๓.๑–๒.๑.๓.๕** (ภายใต้กิจกรรมที่ ๒ ออกแบบระบบบริหารจัดการฯ โดยรวม, TOR.pdf หน้า ๒๓–๒๔) — กำหนดรูปแบบเอกสาร
  (User Flow, Wireframe/Prototype, UI Component Library, Screen Layout/Interaction, Accessibility) — **ข้อเดียวกับที่เล่ม 4 ใช้**
  เพียงแต่คราวนี้ขอบเขตเนื้อหาคือกิจกรรมที่ 7
- **ข้อ ๒.๑.๔** (เดียวกัน) — ออกแบบ Prototype เฉพาะกระบวนงานที่สำคัญ
- **ข้อ ๗.๑–๗.๔** (ภาคผนวก เฉพาะกิจกรรมที่ ๗, TOR.pdf หน้า ๑๗–๑๙) — ขอบเขตฟังก์ชันที่ต้องมี ใช้กำหนดว่าบทที่ 2–5 ต้อง
  ครอบคลุมอะไรบ้าง (รายละเอียดข้อย่อยอยู่ใน "แผนที่ข้อ TOR ↔ หน้าจอ" ท้ายเอกสารนี้)

## บทที่ 3 ผังแผนภาพการไหลของข้อมูล (Data Flow Diagram)

**3.1 Context Diagram (Level 0)**
- External Entity: สายงานต้นทาง (กจ.5), เลขาธิการฯ, ผอ.กบค., ประธานฯ/หน้าห้องประธานฯ, คณะอนุกรรมการกลั่นกรอง,
  คณะอนุสนับสนุนเลขาธิการฯ, ฝ่ายเลขานุการที่ประชุม, คณะกรรมการ ป.ป.ท., ฝ่ายกิจการ, กิจกรรมที่ 4/5/6 (ต้นทาง),
  กิจกรรมที่ 10 (ปลายทาง กรณีอัยการสั่งไม่ฟ้อง/ไม่อุทธรณ์ — นอกขอบเขต)
- Data store กลาง: `tbl_cmp_case`, `tbl_res_request`, `tbl_res_calendar` (Supabase — สร้างและ seed แล้วในสัปดาห์นี้)

**3.2 Data Flow Diagram (Level 1)** — กระบวนการหลักตาม TOR ๗.๑–๗.๔:
1. จัดทำ/จัดเก็บสารบบคดีอิเล็กทรอนิกส์ (๗.๑.๑)
2. คัดแยกรายงานหลังเลขาธิการฯ ลงนาม + มอบสำเนาให้ผู้รับผิดชอบ (๗.๑.๒–๗.๑.๓)
3. สนับสนุนการจัดทำมติ/คำสั่งคณะกรรมการ ป.ป.ท. (๗.๒.๑–๗.๒.๒)
4. จัดทำรายงานวินิจฉัยชี้มูล + หนังสือลงโทษทางวินัย (๗.๒.๓)
5. ค้นหา/กรองข้อมูลคดี (๗.๓)
6. แสดงผลข้อมูล Dashboard (๗.๔)

**3.3 Data Flow Diagram (Level 2)** — หนึ่ง DFD ต่อกระบวนการย่อยในตารางด้านล่าง (แทนที่จะเป็นต่อช่องทางแบบเล่ม 4)
โดยแต่ละ Sub-Process อ้างอิง `ECMIS.TRANSITIONS` โดยตรง (state → state พร้อมเงื่อนไข)
