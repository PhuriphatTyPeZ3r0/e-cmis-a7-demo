มาตรฐานการเขียน Data Flow Diagram สำหรับ E-CMIS

สรุปแนวทางการวาด Context Diagram (Level 0) และ Data Flow Diagram ระดับที่ 1 ที่สรุปได้จากการจัดทำกิจกรรมที่ 7 (ระบบบริหารจัดการกระบวนงานพิจารณาและดำเนินการตามมติคณะกรรมการ ป.ป.ท.) เพื่อให้ทีมนำไปใช้วาด DFD ของกิจกรรมอื่น ๆ ในชุดเดียวกันได้ผลลัพธ์ที่สอดคล้องกัน ทั้งรูปแบบภาพและวิธีจัดเรียงเส้นเชื่อม

อ้างอิงจาก Data Flow Level 0,1,2 กิจกรรมที่ 4, กิจกรรมที่ 14, กิจกรรมที่ 7
รูปแบบไฟล์ .drawio (mxGraph XML)

โครงสร้างไฟล์และการแบ่งหน้า

ไฟล์ .drawio หนึ่งไฟล์ต่อหนึ่งกิจกรรม บรรจุหลายหน้า (diagram) เรียงตามลำดับชั้นของ DFD

หน้าชื่อหน้า (diagram name)เนื้อหา
1Level 0Context Diagram — กระบวนการทั้งกิจกรรมแสดงเป็นกล่องเดียว ล้อมรอบด้วย external entity ทั้งหมด
2Level 1แตกกระบวนการ "0" เป็นกระบวนการย่อยที่มีหมายเลข (1, 2, 3, ...) แต่ละกระบวนการมี entity ของตัวเอง
3+Level 2 (n.n)แตกกระบวนการย่อยที่ซับซ้อนต่อ ถ้าจำเป็น (ใช้รูปแบบเดียวกับ Level 1)

ตั้งชื่อไฟล์ตามแบบ Data Flow Level 0,1,2 กิจกรรมที่ N.drawio หรือ Context Diagram กิจกรรมที่ N.drawio ให้สอดคล้องกับไฟล์ของกิจกรรมก่อนหน้า

สไตล์และสีที่ใช้ตลอดทั้งชุด

ค่าเหล่านี้คัดลอกมาจากไฟล์กิจกรรมที่ 4, 14 และ 7 ตรงกัน — ใช้ค่าเดียวกันทุกกิจกรรมเพื่อความสม่ำเสมอ

ข้อสำคัญ: อย่าใช้สีแยกประเภท entity (เช่น เหลืองสำหรับหน่วยงานภายนอก) — ไฟล์ต้นแบบทุกไฟล์ใช้ขาว-ดำล้วน ระบุความเป็นภายนอก/ภายในด้วยข้อความในกล่องเท่านั้น เช่น "(หน่วยงานภายนอก)"

กฎการวาด Level 0 — Context Diagram

กระบวนการทั้งกิจกรรมแสดงเป็นกล่องเดียวตรงกลาง ล้อมรอบด้วย entity ภายนอก

  1. กล่องกระบวนการกลาง

    ใช้ swimlane ที่มีค่า (value) เป็น "0" เสมอ ข้างในมีกล่องข้อความลูก (child) แสดงชื่อระบบ + ชื่อกิจกรรมเต็ม

  2. ตั้งชื่อ entity แบบ E1, E2, E3...

    เรียงตามลำดับที่ปรากฏในกระบวนการ ไม่ต้องเรียงตามความสำคัญ — ใช้เลขเดิมอ้างอิงต่อใน Level 1 ได้

  3. จัดผังแบบตาราง ไม่ใช่วงกลม

    วาง entity เป็น 4 กลุ่มรอบกล่องกระบวนการ: บน / ล่าง / ซ้าย / ขวา แต่ละกลุ่มเรียงเป็นแถวขนานกับด้านของกล่องกระบวนการ

  4. เส้นเชื่อมทิศทางเดียวต่อ 1 data flow

    ถ้า entity มีทั้งส่งและรับข้อมูล ให้วาด 2 เส้นแยกกัน แต่ละเส้นหัวลูกศรทิศทางเดียวและมี label ของตัวเอง — ห้ามรวมเป็นเส้นเดียวหัวลูกศรสองข้าง

  5. เส้นเชื่อมต้องเป็นเส้นตั้งฉาก (orthogonal)

    ใช้ edgeStyle=orthogonalEdgeStyle และกำหนดจุดเชื่อม entryX/entryY, exitX/exitY ให้ชัดเจนเสมอ ห้ามปล่อยให้โปรแกรมสุ่มจุดเอง

ตัวอย่างการเปรียบเทียบ

✕ ผิด — ผังวงกลม เส้นทแยงมุม

Entity เรียงเป็นวงกลม เส้นทแยงมุมเข้าจุดศูนย์กลางจุดเดียว มองดูรกและไม่ตรงธรรมเนียม DFD

✓ ถูก — ผังตาราง เส้นตั้งฉาก

Entity เรียงเป็น 4 กลุ่มรอบกล่องกระบวนการ เส้นตั้งฉากเข้าจุดต่างกันของแต่ละด้าน ไม่มีเส้นทับ/ตัดกัน

กฎการวาด Level 1 — แตกกระบวนการย่อย

ขยายกล่องกระบวนการ "0" ออกเป็นกระบวนการย่อยที่มีหมายเลขกำกับ ตามลำดับขั้นตอนจริงของงาน

  • ตั้งชื่อกระบวนการย่อยเป็นตัวเลข 1, 2, 3, ... ต่อเนื่องจาก Level 0 พร้อมข้อความอ้างอิงกิจกรรมย่อยในวงเล็บ เช่น [กิจกรรมที่ 7.1]
  • แต่ละกระบวนการย่อยมีกลุ่ม entity ของตัวเอง จัดวางแบบเดียวกับ Level 0 (บน/ล่าง/ซ้าย/ขวา รอบกล่องกระบวนการนั้น ๆ)
  • Entity ที่ใช้ซ้ำในหลายกระบวนการ ให้วาดซ้ำและต่อท้ายด้วย * เช่น E2 ปรากฏในกระบวนการ 1, แล้วปรากฏอีกครั้งในกระบวนการ 3 ให้เขียนเป็น E2* — ห้ามลากเส้นข้ามคลัสเตอร์ไกล ๆ เพราะจะทำให้เส้นตัดกัน
  • วาดเส้นเชื่อมระหว่างกระบวนการ เฉพาะกรณีที่งานไหลต่อกันจริง (เช่น กระบวนการ 1 → 2 → 3) โดยเว้นด้านที่ต้องต่อเชื่อมนั้นว่างจาก entity เพื่อให้เส้นวิ่งผ่านที่ว่างได้โดยไม่ชนกล่องอื่น

ข้อผิดพลาดที่พบระหว่างทำกิจกรรมที่ 7

บันทึกไว้กันพลาดซ้ำ — เรียงตามลำดับที่แก้ไขจริง

✕ ลองก่อน

จัดวาง entity เป็นวงกลมรอบกระบวนการ ลากเส้นตรงทแยงมุมเข้าจุดศูนย์กลาง

ปัญหา: ไม่ตรงธรรมเนียม DFD/ผังงานที่ใช้จริง มองดูเหมือนใยแมงมุม ไม่มีหลักในการอ่าน

✓ แก้เป็น

จัดวาง entity เป็น 4 กลุ่มรอบกล่องกระบวนการ (บน/ล่าง/ซ้าย/ขวา) เส้นตั้งฉาก

ผล: อ่านง่าย ตรงตามผังต้นแบบของกิจกรรมที่ 4 และ 14

✕ ลองก่อน

รวมข้อมูลเข้า-ออกของ entity เดียวกันเป็นเส้นเดียว หัวลูกศรสองข้าง (↔)

ปัญหา: ไม่ตรงหลัก DFD ที่ 1 เส้น = 1 data flow ทิศทางเดียวเสมอ ทำให้อ่านไม่ออกว่าอันไหนคือข้อมูลเข้า อันไหนคือข้อมูลออก

✓ แก้เป็น

แยกเป็น 2 เส้น แต่ละเส้นหัวลูกศรทิศทางเดียว มี label ของตัวเอง

ผล: ตรงตามไฟล์ต้นแบบ อ่านทิศทางข้อมูลได้ชัดเจนทันที

วิธีป้องกันเส้นทับ/ตัดกัน

  • กำหนด entryX/entryY และ exitX/exitY ของทุกเส้นแบบตายตัว อย่าปล่อยให้ drawio หาจุดเชื่อมเอง
  • ในกลุ่ม entity เดียวกัน (เช่น ด้านบนของกระบวนการ) ให้กระจายจุดเชื่อมบนขอบกระบวนการเรียงตามลำดับซ้าย→ขวา ไม่ให้ซ้ำจุดกัน
  • ก่อนบันทึกไฟล์ ให้ตรวจสอบด้วยสคริปต์คำนวณ bounding box ของทุกกล่อง (กระบวนการ + entity + label) ว่าไม่มีคู่ใดทับกัน

Checklist ก่อนส่งงาน

ไล่ทีละข้อก่อนส่งไฟล์ .drawio ให้ทีมตรวจ

  • กล่องกระบวนการกลางของ Level 0 ใช้เลข "0" และมีชื่อระบบ + ชื่อกิจกรรมครบ
  • Entity ทุกตัวตั้งชื่อแบบ E1, E2, E3... ต่อเนื่องไม่ข้ามเลข
  • ทุกเส้นเป็นทิศทางเดียว (1 เส้น = 1 data flow) ไม่มีหัวลูกศรสองข้าง
  • ทุกเส้นเป็นเส้นตั้งฉาก และกำหนด entryX/exitX ชัดเจนแล้ว
  • Entity จัดวางเป็น 4 กลุ่มรอบกระบวนการ ไม่ใช่วงกลม
  • ไม่มีกล่องหรือ label ใดทับกัน (ตรวจด้วยสคริปต์หรือดูด้วยตาในทุกจุด)
  • ใช้ฟอนต์ TH Sarabun New และสีขาว-ดำล้วนตามมาตรฐาน ไม่มีสีแยกประเภท entity
  • Level 1 ใช้ entity ซ้ำแบบมี * ต่อท้าย แทนการลากเส้นข้ามคลัสเตอร์ไกล ๆ
