## 1. สรุป Flow AS-IS 10.1 (สำนวนคดีชั้นอัยการ/ศาล) แบบเต็ม

```
บอร์ด ป.ป.ท. ชี้มูล → เจ้าของสำนวนส่งอัยการ → อัยการตรวจสำนวน
   ├─ [ไม่สมบูรณ์] → ตีกลับ → เจ้าของสำนวนรับตรง → ประเด็นไต่สวนเพิ่ม?
   │      ├─ ทั่วไป (แจ้งข้อหาเพิ่ม) → ลงพื้นที่ → รายงานบอร์ด → เห็นชอบ → ส่งอัยการใหม่ (วนกลับ "อัยการตรวจสำนวน")
   │      └─ อัยการสั่งแยกสำนวน → เสนอบอร์ด → รับเป็นเรื่องใหม่ → เริ่มไต่สวนออกเลขใหม่ (จบ เข้ากิจกรรมที่ 5 ใหม่)
   ├─ [ไม่สั่งฟ้อง] → ธุรการ กม. ออกเลขรับ/มอบหมาย → นิติกรตรวจสอบเสนอ → บอร์ด ป.ป.ท. พิจารณามติ
   │      ├─ เห็นชอบ → จบ (คดีอาญายุติ)
   │      └─ เห็นแย้ง (ยืนฟ้อง ม.46) → อสส. ชี้ขาด
   │             ├─ ไม่ฟ้อง/ไม่อุทธรณ์ → จบคดี
   │             └─ สั่งฟ้อง/สู้คดี → (เข้าสู่เส้นทาง "สั่งฟ้อง" ด้านล่าง)
   └─ [สั่งฟ้อง] → แจ้งนัด ป.ป.ท. นำตัวส่งศาล → เจ้าของสำนวนแจ้งผู้ถูกกล่าวหา → มาตามนัด?
          ├─ มา → นำตัวส่งอัยการ → อัยการนำส่งฟ้องศาล → ศาลพิพากษา
          └─ ไม่มา → อัยการแจ้งขอหมายจับ → เจ้าของสำนวนยื่นคำร้อง → ศาลอนุมัติหมายจับ
                 → ประสานตำรวจติดตามจับกุม → จับได้ส่งอัยการ → รายงานเลขาธิการฯ/ศาลขอยุติหมายจับ
                 → อัยการนำส่งฟ้องศาล → ศาลพิพากษา

ศาลพิพากษา (ทุกเส้นทางมาบรรจบที่นี่) → ส่งสำเนาคำพิพากษา → ผลคำพิพากษา?
   ├─ [ลงโทษ] → ธุรการ กม. ออกเลขรับ → นิติกรเชื่อมโยงข้อมูล "กิจกรรมที่ 8" → จบกระบวนการ
   └─ [ยกฟ้อง/ไม่ครบ] → อัยการพิจารณาอุทธรณ์/ฎีกา?
          ├─ สู้คดีต่อ → วนกลับเข้า "ศาลพิพากษา" (ชั้นถัดไป: อุทธรณ์ → ฎีกา)
          └─ ไม่อุทธรณ์ → ธุรการ กม. ออกเลขรับ → นิติกรตรวจสอบเสนอ → บอร์ด ป.ป.ท. พิจารณามติ
                 ├─ เห็นชอบ → จบ (คดีอาญาสิ้นสุด)
                 └─ เห็นแย้ง → ส่ง อสส. ชี้ขาด (ม.46) (วนกลับเข้า อสส. ชี้ขาด)
```

**ข้อสังเกตสำคัญ:** เส้นทาง "สั่งฟ้อง" (ฟ้อง → พิจารณาคดี → หมายจับ ถ้าจำเป็น → พิพากษา 3 ชั้น) เป็นเส้นทางที่ **ยาวและซับซ้อนที่สุด** ใน Flow แต่ TOR ข้อ ๑๐.๑.๑.๑ เอ่ยถึงเฉพาะ "ประเภทสำนวน" ฝั่งที่อัยการ**ไม่ฟ้อง**เท่านั้น (ไม่ฟ้อง/ถอนฟ้อง, ไม่อุทธรณ์/ถอนอุทธรณ์, ไม่ฎีกา/ถอนฎีกา) — ในขณะที่ TOR ข้อ ๑๐.๑.๔ กลับระบุให้ "บันทึกคำพิพากษาศาลทั้ง 3 ชั้น (ชั้นต้น, อุทธรณ์, ฎีกา)" ซึ่งเกิดได้เฉพาะเมื่อคดี**ถูกฟ้อง**เท่านั้น จึงสรุปได้ว่า TOR ต้องการให้ระบบติดตามคดีได้ **ทั้ง 2 เส้นทาง** ไม่ใช่เฉพาะฝั่ง "ไม่ฟ้อง" — นี่คือช่องว่างหลักที่พบ

## 3. ประเด็นเพิ่มเติมที่พบระหว่างวิเคราะห์ (ไม่ใช่ Gap แต่ควรบันทึกไว้)

- **10.3 — ทิศทางอุทธรณ์หลังพิพากษา:** Flow แยกชัดเจนว่า "ชนะคดี" อาจถูก**ผู้ฟ้องอุทธรณ์เอง** (ป.ป.ท. เป็นฝ่ายตั้งรับ) ในขณะที่ "แพ้คดี" ต้องให้**บอร์ด ป.ป.ท. มีมติว่าจะอุทธรณ์เองหรือไม่** — สองเส้นทางนี้มีเจ้าของการตัดสินใจต่างกัน ควรมี field "ผู้ยื่นอุทธรณ์: ผู้ฟ้อง / ป.ป.ท." ใน W4 เพื่อให้ Timeline/รายงานแยกออกจากกันได้ถูกต้อง (ปัจจุบันมี Alert สิทธิอุทธรณ์ แต่ยังไม่แยกฝ่ายผู้ยื่น)
- **10.3 — ชดใช้ค่าเสียหาย:** ขั้นตอนสุดท้ายก่อนปิดสำนวน ("ชดใช้ค่าเสียหาย(ถ้ามี) บันทึกคดีถึงที่สุด/ปิดสำนวน") ยังไม่มี field ทางการเงินใน W4 — เสนอเพิ่มเป็น field เสริม (จำนวนเงิน, เลขที่อ้างอิงการเบิกจ่าย) เพื่อรองรับการรายงานเชิงสถิติ แต่ไม่กระทบ TOR ข้อ ๑๐ โดยตรง (เป็นมูลค่าเพิ่ม)
- **10.1 — ธุรการกองกฎหมาย ปรากฏ 3 จุดซ้ำ** ในผังงาน (รับความเห็นไม่สั่งฟ้อง / รับคำพิพากษา / รับความเห็นไม่อุทธรณ์) แต่ทำหน้าที่เดียวกันทุกครั้ง (ออกเลขรับ + มอบหมาย) — ยืนยันว่า Modal 1+2 ของ W1 ที่ใช้ pattern เดียวกันซ้ำได้ครบทั้ง 3 จุดอยู่แล้ว ไม่ต้องออกแบบเพิ่ม (ไม่ใช่ Gap)
