# กิจกรรมที่ 7: กระบวนงานพิจารณาและดำเนินการตามมติคณะกรรมการ ป.ป.ท.
## เอกสารสรุปฉบับสมบูรณ์ — กรอบกฎหมาย ผังกระบวนงาน แผนทดสอบ และสถานะการพัฒนาหน้าจอ

เอกสารฉบับนี้รวบรวมผลการทบทวนกฎหมาย การออกแบบกระบวนงาน แผนการทดสอบ และสถานะการพัฒนาต้นแบบหน้าจอของ "กิจกรรมที่ 7" (เริ่มจากเลขาธิการคณะกรรมการ ป.ป.ท. สั่งให้ดำเนินการต่อไป จนถึงมติชี้มูล/ไม่มีมูลของคณะกรรมการ ป.ป.ท.) ไว้เป็นชุดเดียว เพื่อใช้ประกอบการพิจารณาของสำนักงาน ป.ป.ท.

## ส่วนที่ 2 ตารางความเชื่อมโยงกับหน่วยงานและกิจกรรมที่เกี่ยวข้อง (Integration Matrix)

## ส่วนที่ 3 ข้อสังเกตเรื่องการเทียบเคียงบทบาท (Actor Mapping Notes)

- **"คณะอนุกรรมการกลั่นกรองฯ"** ไม่ปรากฏชื่อนี้ตรงตัวในตัวบทกฎหมาย — ตำแหน่งที่ใกล้เคียงที่สุดคือ **"คณะอนุกรรมการไต่สวน"** (ม.24 วรรคสาม) หรือหน้าที่กลั่นกรองเบื้องต้นที่คณะกรรมการ ป.ป.ท. **มอบหมายให้เลขาธิการ**ทำโดยตรง (ม.28) — ควรยืนยันกับทีมกฎหมายก่อนกำหนดชื่อบทบาทในระบบอย่างเป็นทางการ
- **"นิติกรเจ้าของเรื่อง"** ไม่ปรากฏชื่อนี้ตรงตัวเช่นกัน — ตัวบทใช้คำว่า **"พนักงาน ป.ป.ท."** และ **"เจ้าหน้าที่ ป.ป.ท."** (นิยามตามมาตรา 3)
- เลขหน้าที่อ้างอิงในตารางส่วนที่ 1 คือเลขหน้าที่พิมพ์ในเนื้อหาตัวบทกฎหมาย ไม่ใช่เลขหน้าของไฟล์ PDF

## ส่วนที่ 4 การเปรียบเทียบกระบวนงานเดิมกับกระบวนงานใหม่ (AS-IS vs TO-BE)

ผังกระบวนงาน TO-BE ของกิจกรรมที่ 7 ในไฟล์ต้นแบบ (หน้า "TO-BE P1 Context และ Integration", "TO-BE P2 Core Workflow" และ "TO-BE P3 Exception และ Alternative Flows") มีความสมบูรณ์อยู่ในระดับสูงอยู่แล้ว มีจุดเริ่มต้นที่เลขาธิการฯ กลไก "มติโดยปริยาย" ตามมาตรา 28 และฟังก์ชันดิจิทัลหลัก (Auto-fill/Validation/Routing/e-Approval/Mail-Merge/SLA Timer) ครบถ้วนอยู่แล้ว จึงไม่จำเป็นต้องออกแบบผังใหม่ทั้งหมด แต่เมื่อตรวจเทียบกับตารางกฎหมายและ Integration Matrix ข้างต้น พบช่องว่างที่ยังไม่ตรงตามตัวบทหรือยังไม่ครบตามขอบเขตงาน 6 จุด ดังนี้:

1. โหนดจุดเริ่มต้น (`t5`) ยังไม่อ้างอิง **ม.18/4(2)** ซึ่งเป็นฐานอำนาจที่แท้จริงของจุดเริ่มกิจกรรมที่ 7 (เดิมอ้างอิงเฉพาะ SLA ของรายงาน 213/644)
2. ไม่มี SLA Alert สำหรับ **ม.23 วรรคหนึ่ง — ต้องเริ่มไต่สวนภายใน 60 วัน**นับแต่ได้รับเรื่อง/ความปรากฏ ตรวจสอบทั้งผังแล้วไม่พบจุดนี้ในเส้นทางหลักเลย มีเพียงบทลงโทษกรณีล่าช้าปรากฏอยู่ในผังข้อยกเว้น (EX-12/`s12d`)
3. ม.28 (15 วัน) มีอยู่แล้วในผังข้อยกเว้น (EX-10, หน้า 3) แต่ยังไม่ปรากฏเป็น SLA Alert ในผังหลัก (หน้า 2) ที่จุดเริ่มต้นกิจกรรม
4. ช่อง Digital Platform Services (`p1p`) มีครบเพียง 6 กล่อง ยังไม่ครบ **7 ฟังก์ชันดิจิทัลหลัก**ตามขอบเขตงาน — ขาด "Data Ingestion" และ "Real-time Dashboard" ที่ควรแยกเป็นกล่องชัดเจน (เดิมมีเพียงคำอธิบายแทรกอยู่ในกล่องอื่น)
5. จุดเชื่อมภายนอกตาม Integration Matrix (ส่วนที่ 2) ยังขาด: ศาลที่มีเขตอำนาจ (หมายจับ ม.19/2), ศาลทหาร (ม.45), ก.พ.ค. (ม.43), นายกรัฐมนตรี (ม.42), คณะรัฐมนตรี (ม.46 วรรคสอง), หน่วยงานของรัฐทั่วไป (ม.17/1(4), ม.19) — และกล่อง `p1x3` ใช้ชื่อ "ศาลปกครอง" ซึ่งไม่ตรงกับตัวบท (ม.43 ระบุ "ศาลปกครองสูงสุด")
6. กล่องกิจกรรมที่ 4/5/8/10 (`p1a4`, `p1a5`, `p1a8`, `p1a10`) ยังไม่มีป้าย **"สันนิษฐาน"** ทั้งที่ยังไม่มีสเปกกระบวนงานของกิจกรรมเหล่านั้นให้อ้างอิงได้ และเป็นเพียงการอนุมานจากตำแหน่งในกระบวนงานโดยรวมเท่านั้น

## ส่วนที่ 11 สถานะการพัฒนาต้นแบบหน้าจอ

### 11.1 องค์ประกอบที่มีอยู่แล้วในระบบ (ไม่ได้สร้างใหม่)

หน้าจอ "11-secgen-desk.html" (โต๊ะสั่งการของเลขาธิการฯ) มีความสมบูรณ์อยู่แล้วในระดับสูง ครอบคลุมคิวลงนาม (S1) คิวรายงานตามรอบมาตรา 28 คิวคำสั่งแต่งตั้งองค์คณะตามมาตรา 24 วรรคหนึ่ง การแจ้งเตือน SLA และแผงอ้างอิงอำนาจการวินิจฉัยของเลขาธิการฯ ส่วนหน้าจอ "04-approval-review.html" มีกล่องโต้ตอบลงนามด้วยรหัส OTP แบบผู้ลงนามเดี่ยว แผงสิทธิ์ส่งคืน/ดึงเรื่องกลับ และตรรกะเงื่อนไข G1/G3 อยู่แล้ว จึงคงองค์ประกอบเหล่านี้ไว้ตามเดิม และขยายเพิ่มเติมเฉพาะส่วนที่ระบุด้านล่าง

### 11.2 ช่องว่างที่พบและดำเนินการแก้ไขแล้ว

1. คำสั่งเบื้องต้น 3 ทางตามมาตรา 28 (รับไว้พิจารณา / ไม่รับไว้พิจารณา / จำหน่ายเรื่อง ซึ่งมีโมเดลข้อมูลรองรับอยู่แล้วใน `ECMIS.M28_ORDERS`) ยังไม่มีหน้าจอให้เลือกใช้งานจริง ปุ่ม "ลงนาม" ของเลขาธิการฯ จึงหมายถึงการรับไว้พิจารณาเพียงทางเดียวเสมอ
2. ยังไม่มีปุ่มคำสั่ง "มอบหมาย" ในผังงานของเลขาธิการฯ เลย มีเพียงการกำหนดเส้นทางโดยอ้อมผ่านช่องกาเครื่องหมาย "ซับซ้อน" เท่านั้น
3. การลงนามอิเล็กทรอนิกส์รองรับผู้ลงนามเดี่ยวเท่านั้น (`ECMIS.signDialog`) ยังไม่มีกลไกลงนามตามลำดับหลายคน ทั้งที่กติกาของเงื่อนไข G3 กำหนดไว้แล้วว่าต้องมีลายมือชื่อรับรองลำดับที่สอง (ผู้อำนวยการกองบริหารคดี) ก่อนจึงจะข้ามขั้นตอน (Bypass) ได้

### 11.3 รายการไฟล์ที่แก้ไข/เพิ่มเติม

การเปลี่ยนแปลงทั้งหมดอยู่บนบรานช์ `Mock-up-7` เป็นการแก้ไขที่ค้างอยู่ในเวิร์กทรี ยังไม่มีการบันทึกเข้าประวัติ git (commit) — รอการตรวจทานก่อน:

```
 M activity7/04-approval-review.html
 M activity7/11-secgen-desk.html
 M activity7/assets/ecmis-app.js
```

- `activity7/assets/ecmis-app.js` — เพิ่มฟังก์ชัน `sequentialSignDialog(docName, signers)` เป็นกล่องโต้ตอบลงนามอิเล็กทรอนิกส์แบบหลายคนที่ใช้ซ้ำได้ (แสดงลำดับผู้ลงนามทั้งชุด รับ OTP ได้เฉพาะผู้ลงนามลำดับปัจจุบัน ผู้ลงนามลำดับถัดไปแสดงสถานะ "รอดำเนินการในขั้นตอนถัดไปของผัง") และ export ควบคู่กับ `signDialog` เดิม ไม่มีฟังก์ชันเดิมที่ถูกแก้ไข
- `activity7/04-approval-review.html` — เพิ่มตัวเลือกคำสั่งเบื้องต้น 3 ทางตามมาตรา 28 (`#m28Card`, `#m28List` ดึงข้อมูลจาก `ECMIS.M28_ORDERS`, `#m28Law` สำหรับอ้างอิงมาตราเมื่อไม่รับไว้พิจารณา) ที่ควบคุมการแสดงผลของกล่อง G1/G3 เดิมและแยกเส้นทางของปุ่มลงนาม (กรณีรับไว้พิจารณา ใช้เส้นทาง G1/G3 เดิม กรณีไม่รับไว้พิจารณา/จำหน่ายเรื่อง ปิดสำนวนพร้อมข้อความอ้างอิงมาตรา 28); เพิ่มปุ่ม "มอบหมาย" (`data-act="assign"`) ที่ตั้งค่า G1 = ใช่ ล่วงหน้าแล้วนำเข้าสู่ขั้นตอนลงนาม; เชื่อม `ECMIS.sequentialSignDialog` เข้ากับเส้นทางใบด่วน G3 (เลขาธิการฯ → ผอ.กบค.) แทนกล่องโต้ตอบผู้ลงนามเดี่ยวเดิม; เพิ่มการรับพารามิเตอร์ `?assign=1` เพื่อให้ปุ่ม "มอบหมาย" จากหน้าคิวรวมเติมข้อมูลล่วงหน้าให้หน้านี้ได้
- `activity7/11-secgen-desk.html` — เพิ่มปุ่มคำสั่งด่วนระดับแถว ("มอบหมาย" และ "ตีกลับ") ในตารางคิวลงนาม S1 โดยใช้ `ECMIS.RETURN_REASONS` / `ECMIS.RETURN_SCOPES` / `ECMIS.confirmAction` / `ECMIS.toastOk` ชุดเดียวกับที่ใช้ในหน้า "เห็นชอบ / ลงนาม" เพื่อความสอดคล้องกัน ส่วนลิงก์ "เห็นชอบ / ลงนาม" เดิมคงไว้ไม่เปลี่ยนแปลง เนื่องจากการอนุมัติเต็มรูปแบบยังต้องมีการบันทึกความเห็นและลงนามดิจิทัลตามกฎหมาย ไม่สามารถลัดขั้นตอนจากปุ่มเดียวในหน้าคิวรวมได้

ไม่มีการสร้างไฟล์ใหม่ทั้งหมด เป็นการขยายหน้าจอเดิมที่ครอบคลุมกระบวนงานกล่องขาเข้าและการดำเนินการของเลขาธิการฯ อยู่แล้ว

### 11.4 การตรวจสอบไม่ให้กระทบของเดิม (Regression Check)

## ส่วนที่ 12 UI Strings & Label Matrix (ตารางคำศัพท์บนหน้าจอที่ปรับแก้แล้ว)

ได้ตรวจสอบข้อความบนหน้าจอทั้ง 3 ไฟล์ที่แก้ไขในรอบนี้ (`activity7/04-approval-review.html`, `activity7/11-secgen-desk.html`, `activity7/assets/ecmis-app.js`) โดยเฉพาะส่วนที่เพิ่มใหม่ ได้แก่ ตัวเลือกคำสั่งเบื้องต้น 3 ทางตามมาตรา 28, กล่องโต้ตอบลงนามอิเล็กทรอนิกส์ตามลำดับ (Sequential e-Signature) และปุ่มคำสั่งด่วน "มอบหมาย/ตีกลับ" ในหน้าคิวรวม

**ผลการตรวจสอบ: ไม่พบข้อความที่ต้องแก้ไข** ข้อความบนหน้าจอทั้งหมดที่เพิ่มเข้ามาในรอบนี้ใช้ศัพท์ทางการที่ตรงกับตัวบทกฎหมายและใช้ในระบบเดิมอยู่แล้ว (เช่น "มอบหมายเข้าคณะอนุสนับสนุนฯ", "ส่งคืนสายงานต้นทาง", "ลงนามดิจิทัลและส่งต่อ", "ลงลายมือชื่อดิจิทัลตามลำดับ", "รหัส OTP ที่ส่งไปยังโทรศัพท์ที่ลงทะเบียนของ...") ไม่มีร่องรอยของการแปลเชิงกลไก คำทับศัพท์ที่ไม่จำเป็น หรือถ้อยคำที่ไม่ตรงกับบริบทงานราชการ จึงไม่มีรายการให้ปรับแก้ในตารางนี้
